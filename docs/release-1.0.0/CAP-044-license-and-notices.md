# CAP-044 — Licence, notices and third-party attributions

| Epic | Priority | Points | Depends on | Status |
|---|---|---|---|---|
| E9 Lifecycle & release | P0 | 1 | — | Implemented |

## User story
As a **maintainer shipping capellactl as source code to every team**, I want the licence chosen, written down and checked, so that everyone receiving the code knows what they may do with it and we meet the obligations of the libraries we depend on.

## Context & discovery
As built today:
- `pyproject.toml` declares `license = { text = "Apache-2.0" }`, but the repository has no `LICENSE` or `NOTICE` file. Nothing records who holds the copyright.
- Runtime dependencies (`click`, `requests`, `PyYAML`, `jsonschema`, `rich`, `keyring`, `ruamel.yaml`) and their own dependencies each carry a licence. No list of them exists, and nothing checks that they are compatible with ours.
- CAP-043 (distributables) needs these files to exist so they can be included in the source archive and wheel.

## Implementation details
- `LICENSE` at the repository root: the unmodified Apache License 2.0 text (decided 2026-10-05, see below).
- `NOTICE`: product name, the copyright line `Copyright 2026 Couchbase, Inc.`, the author line `Author: Anuj Sahni, Principal Cloud & Solutions Architect`, and the attribution required by Apache-2.0 §4(d).
- `pyproject.toml`: SPDX form `license = "Apache-2.0"` and `license-files = ["LICENSE", "NOTICE"]`, so the wheel and sdist metadata carry them.
- `THIRD_PARTY_NOTICES.md`: generated by `scripts/third-party-notices.py` from the installed runtime dependencies (name, version, licence, project URL). `make notices` regenerates it.
- A licence policy (`scripts/licence-policy.json`) lists the allowed licences (for example Apache-2.0, MIT, BSD-2/3-Clause, PSF, ISC, MPL-2.0). CI fails when a runtime dependency has a licence outside the list, or when `THIRD_PARTY_NOTICES.md` is stale.
- README gets a short **Licence** section linking `LICENSE`, `NOTICE` and `THIRD_PARTY_NOTICES.md`.

## Acceptance criteria & tests

### AC1 — Licence file matches the declared licence
**Given** the repository, **then** `LICENSE` exists with the full licence text, and the SPDX identifier in `pyproject.toml` matches it. A test fails if either is missing or they disagree.

|---|---|---|
| `test_licence_ac1_file_matches_pyproject` | `tests/unit/test_licence.py` | SHA-256 of the apache.org text; SPDX id in `pyproject.toml` and `capellactl.LICENSE` |

### AC2 — Copyright and notice recorded
**Given** the repository, **then** `NOTICE` names the product and contains `Copyright 2026 Couchbase, Inc.`, and `capellactl --version` prints `Licensed under <SPDX id>`.

| Test | Location | Verifies |
|---|---|---|
| `test_licence_ac2_notice_and_version_line` | `tests/unit/test_licence.py` | |

### AC3 — Third-party attributions listed and current
**Given** the runtime dependencies resolved from `pyproject.toml`, **then** `THIRD_PARTY_NOTICES.md` lists each one with version and licence. CI fails when the file is out of date (`scripts/third-party-notices.py --check`).

| Test | Location | Verifies |
|---|---|---|
| `test_licence_ac3_third_party_notices_current` | `tests/unit/test_licence.py` | Also `test_licence_ac3_stale_file_detected` |

### AC4 — Dependency licences are compatible
**Given** the licence policy, **when** a runtime dependency (direct or transitive) has a licence outside the allowed list (or an unknown licence), **then** CI fails and names the package and its licence.

| Test | Location | Verifies |
|---|---|---|

### AC5 — Metadata carries the licence
**Given** the wheel and sdist built by CAP-043, **then** their metadata has `License-Expression: Apache-2.0` and includes `LICENSE` and `NOTICE` as licence files.

| Test | Location | Verifies |
|---|---|---|
| `test_licence_ac5_wheel_metadata` | `tests/unit/test_packaging.py` | Builds the wheel offline (`--no-build-isolation`) |

## Out of scope
- Licence headers in source files (decided against; see Decisions).
- A contributor licence agreement (CLA) or DCO sign-off process.

## Decisions
- **Copyright holder: Couchbase, Inc.** (decided 2026-10-05; first recorded as Anuj Sahni personally, changed the same day because the work belongs to the employer). `NOTICE` reads `Copyright 2026 Couchbase, Inc.` and credits the author on a separate line: `Author: Anuj Sahni, Principal Cloud & Solutions Architect`.
- **No per-file licence headers** (decided 2026-10-05). The licence terms live only in the separate `LICENSE` file at the repository root (with `NOTICE` for the copyright line), and source files carry no SPDX or licence header. `LICENSE` and `NOTICE` ship in both the source archive and the wheel (AC5, CAP-043 AC4).
- **Licence: Apache-2.0** (decided 2026-10-05 by the code owner). capellactl contains no Couchbase Server code (it only calls the Capella Management API), so Couchbase Server's BSL 1.1 does not apply. Apache-2.0 was preferred over BSL 1.1 because it is OSI-approved open source with an explicit patent grant, and teams can adopt it without a legal review; the BSL alternative would only add value if commercial resale of capellactl had to be prevented.

## Implementation notes (as built)

- **`LICENSE`** is the unmodified Apache License 2.0 text downloaded from apache.org (SHA-256 `cfc7749b…3d30`, checked by AC1). **`NOTICE`** holds `capellactl`, `Copyright 2026 Couchbase, Inc.`, the author line and pointers to `LICENSE` and `THIRD_PARTY_NOTICES.md`. Source files carry no licence header.
- **`pyproject.toml`** uses PEP 639: `license = "Apache-2.0"`, `license-files = ["LICENSE", "NOTICE"]`, and build requirement `hatchling>=1.27`. The wheel's metadata has `License-Expression: Apache-2.0` and ships both files under `.dist-info/licenses/`. `hatchling` and `packaging` were added to the `dev` extra, so tests can build the wheel offline and the notices script can parse requirements.
- **AC2:** `capellactl --version` keeps its first line (CAP-001 AC1) and adds a second: `Licensed under Apache-2.0 · Copyright 2026 Couchbase, Inc.` (`capellactl.LICENSE`, `capellactl.COPYRIGHT`).
- **AC3 (deviation): versions are listed but not compared by `--check`.** Installed versions differ between CI jobs, and so does the set of packages: `keyring` pulls in SecretStorage, jeepney, cryptography, cffi and pycparser only on Linux, pywin32-ctypes only on Windows, and backports/importlib-metadata/zipp/typing_extensions only on older Pythons.
  - **Generating** (`make notices`, needs network) walks the whole requirement graph with platform/Python markers kept as a "Needed" column. It reads metadata from installed packages, or from PyPI's JSON API for packages not installed here.
  - **Checking** (`--check`, offline, run by CI on every OS × Python job and by `make check`) fails when an installed runtime dependency is missing from the file, its licence differs, or its licence is not allowed.
  - First generation: 32 packages, 9 of them platform- or Python-specific.
- **AC4:** `scripts/licence-policy.json` allows 0BSD, Apache-2.0, BSD-2-Clause, BSD-3-Clause, ISC, MIT, MIT-0, MIT-CMU, MPL-2.0, PSF-2.0, Python-2.0 and Unlicense. SPDX expressions are evaluated (`OR`: either side allowed, `AND`: both, `WITH`: the base licence). Licences come from `License-Expression`, else a short `License` field, else the trove classifiers; anything else is `UNKNOWN` and refused.
  - MIT-0 was added after the first run flagged cffi 2.1.1 (Linux only), which declares MIT-0 ("MIT No Attribution", more permissive than MIT).
  - The only weak-copyleft dependency is certifi (MPL-2.0), used unmodified.
- **Build paths updated:** the Dockerfile copies `LICENSE` and `NOTICE` into its build stage (required now that they are declared licence files); CI runs `scripts/third-party-notices.py --check`; `make notices` / `make notices-check` added, the latter part of `make check`.
- **Docs:** README **Licence** section; CONTRIBUTING "Dependencies and licences".
