# CAP-008 — Secret redaction & credential output files

| Epic | Priority | Points | Depends on | Status |
|---|---|---|---|---|
| E1 Foundation | P0 | 3 | CAP-002, CAP-003 | Implemented |

## User story
As a **security reviewer**, I want a guarantee that API keys and database passwords never appear in output, logs or errors, and that passwords Capella generates are stored safely, so that the tool can be approved for production use.

## Context & discovery
- `POST …/clusters/{clusterId}/users` returns `{id, password}` (201); the password is returned **only** there. `GET` never returns it.
- Passwords may come from env vars, files, or be generated by Capella.

## Implementation details

| Module | Responsibility |
|---|---|
| `output/redact.py` | Global `Redactor` with registered secret values (API key, every resolved `password`, every generated password); `redact(str) -> str`; `redact_obj(obj)` masks any key named `password`/`Authorization`; installed as a `logging.Filter` and wrapped around all render functions and the top-level exception handler |
| `output/secrets_out.py` | `write_generated_credential(dir, cluster, name, id, password)` → `<dir>/<cluster>.<name>.json`, created with `os.open(..., 0o600)`; directory created `0o700`; refuses to overwrite unless `--force-overwrite-secret` |
| `output/gitcheck.py` | Detects whether a path is inside a git work tree and not ignored (`git check-ignore`) |

## Acceptance criteria & tests

### AC1 — Redaction canary across all channels
**Given** a canary API key and canary password, **when** a scenario runs `validate`, `plan`, `apply`, a forced API error and `--log-level debug`, **then** neither canary appears in stdout, stderr, log records or exception text.

| Test | Location | Verifies |
|---|---|---|
| `test_redaction_ac1_canary_never_printed` | `tests/scenario/test_redaction.py` | `assert_no_secret` across channels |
| `test_redact_ac1_masks_registered_values` | `tests/unit/output/test_redact.py` | |
| `test_redact_ac1_masks_password_keys_in_objects` | same | Nested dicts and lists |

### AC2 — Generated password file
**Given** a credential created without `password`, **then** the 201 password is written to `./.capellactl/credentials/nova-dev-01.web_sessions.json` with mode `0600` containing `{cluster, name, id, password, createdAt}`, and the terminal shows only `password saved to ./.capellactl/credentials/nova-dev-01.web_sessions.json`.

| Test | Location | Verifies |
|---|---|---|
| `test_secrets_out_ac2_file_mode_and_content` | `tests/unit/output/test_secrets_out.py` | `stat` mode, JSON keys (POSIX only) |
| `test_secrets_out_ac2_terminal_shows_path_only` | `tests/scenario/test_credential_create.py` | |

### AC3 — Never overwrite a saved secret silently
**Given** the target file already exists, **then** the write fails with exit 1 `refusing to overwrite <path>; move it or pass --force-overwrite-secret` **before** the credential is created (pre-flight check).

| Test | Location | Verifies |
|---|---|---|
| `test_secrets_out_ac3_preflight_refuses_overwrite` | `tests/scenario/test_credential_create.py` | No POST sent |

### AC4 — Git safety warning
**Given** `credentialsOutput` inside a git work tree and not ignored, **then** `apply` prints `warning: ./.capellactl/credentials is not git-ignored; add .capellactl/ to .gitignore` before writing.

| Test | Location | Verifies |
|---|---|---|
| `test_gitcheck_ac4_warns_when_not_ignored` | `tests/unit/output/test_gitcheck.py` | Temp git repo |
| `test_gitcheck_ac4_silent_when_ignored` | same | |

### AC5 — Exceptions are redacted
**Given** an unexpected exception whose message contains a secret, **then** the top-level handler prints the redacted message and, with `--log-level debug`, a redacted traceback.

| Test | Location | Verifies |
|---|---|---|
| `test_redaction_ac5_uncaught_exception_redacted` | `tests/scenario/test_redaction.py` | |

## Out of scope
- Integrations with external secret managers (Vault, AWS Secrets Manager) beyond `${VAR}` / `${file:…}` — candidate for 1.1.

## Open questions
- Windows: `0600` has no direct equivalent; proposed behaviour is to set an owner-only ACL via `icacls` or warn. Confirm with the customer's Windows team.

## Implementation notes (as built)
- AC2/AC3 are verified at the function level (`write_generated_credential`, `preflight`, `saved_message`). Wiring them into `credential create` happens in CAP-027, whose ACs reuse these functions.
